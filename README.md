# 个人电脑 MCP 插件搭建提示词

复制下方提示词，在自己的 Codex 中使用。请使用自己的设备、账号和工作区完成部署与验收。

```text
请在我的电脑上创建、部署并验证一个个人 MCP 插件，名称为“项目资料（完整文件访问）”。

目标：让我在 ChatGPT 网页端通过这个插件读取和修改本机文件、分析代码结构、执行终端命令、启动服务及管理进程。请完成实际开发和接入，不要只交付方案或演示代码。

先识别实际执行机器、操作系统、当前用户、已有依赖和相关配置，遵循本机适用的 AGENTS.md。普通实现细节自行决定，简要说明后持续执行；需要我本人处理账号登录、密钥输入或系统授权时，再指出具体步骤。

一、连接方式

采用：
ChatGPT → OpenAI 官方 Secure MCP Tunnel → 本机 MCP 服务 → 本机文件与 Shell。

1. 使用官方 tunnel-client，核对当前官方文档及 CLI 帮助，不凭旧版本经验猜命令。
2. 创建或复用属于我本人账号、Platform 组织和目标 ChatGPT 工作区的隧道。
3. 核对隧道的组织/工作区关联与权限：创建管理需要相应 Manage 权限，运行及使用需要相应 Use 权限。
4. 本机服务优先使用标准 stdio MCP，以便同时提供本机 Codex 可用的连接配置。
5. 网页中创建并安装私人自定义 MCP 插件，连接方式选择 Tunnel，刷新并检查实际工具列表。
6. 不复用别人的 tunnel_id、插件 ID、运行密钥、账号或机器路径。不接入 Desktop Commander 等第三方转发服务。
7. 密钥由我在本机安全输入，使用受保护文件或环境引用；不要让我把密钥、Cookie、Token 发到聊天，也不要把它们写进源码、普通日志或截图。
8. 根据我账号和工作区的实际条件配置；缺少平台权限时准确说明，不假定某个订阅必然包含全部能力，也不要绕过平台限制。

二、权限要求

我明确授权：为这个私人插件开放当前操作系统用户实际拥有的完整文件访问和 Shell 执行能力。

1. 文件范围包括当前用户目录、已挂载磁盘及系统文件根目录中该用户有权访问的路径。macOS 对应用户目录、/Volumes 和 /；其他系统按实际目录、盘符适配。
2. 不额外限制为某个项目目录；不添加隐藏文件、应用配置、敏感文件名、扩展名或凭据内容的自定义过滤。允许正常使用符号链接和硬链接。
3. 完整访问不等于自动扫描全盘；只读取当前任务相关资料。
4. 不自动提权，不绕过操作系统的文件权限、隐私授权或系统保护。确实需要系统授权时由我本人完成。
5. 将这个插件单独设置为“允许所有操作 / Allow all actions / full_access”。保持账号全局默认和其他插件的权限设置不变。
6. 正确标注 MCP 工具的读取、写入、破坏性及外部影响属性，不把写入或执行工具伪装成只读。
7. 这是私人使用插件，不公开发布，也不将本机服务暴露成无认证公网服务。

三、文件与资料能力

提供以下工具：
list_roots、list_directory、inspect_file、read_file、
search_file、read_media、read_bytes、stat_path、
write_file、edit_file、create_directory、copy_file、
move_path、delete_path。

要求：

- 支持目录分页、文件状态查询、文本读取、搜索、创建、覆盖、追加、精确文本替换、复制、移动及重命名。
- 修改已有文件必须带 expected_version 等版本令牌；文件已被其他程序修改时拒绝旧请求，防止覆盖新内容。
- 创建文件默认拒绝覆盖已有文件；复制或移动到已有目标时也应明确拒绝。
- 文本、目录和原始字节支持分页；未知格式或超出解析大小的普通文件仍能分页读取原始字节，不把“无法解析”误报为“没有权限”。
- 提供 PDF、DOCX、PPTX、XLSX 文本提取，以及图片、PDF 页面、视频帧预览。视觉结果返回实际 MCP 图像内容，不能只返回本机路径。不要执行文档宏。
- 参考解析上限：文本 20 MiB，Office/PDF 50 MiB，图片 20 MiB，视频 512 MiB；原始字节读取不设文件总大小白名单。单次字节读取最多 64 KiB，单次写入最多 256 KiB，大文件分块处理。
- 读取后续分页时绑定文件版本，文件变化则提示重新读取。
- 写入、编辑应尽可能保留原有编码信息、换行、权限与链接语义；发生部分写入时如实报告，不声称操作未发生。

删除的固定约定：

- delete_path 只能移入操作系统的废纸篓/回收站。
- 不提供永久删除或清空废纸篓选项。
- 移入失败就报错，不退化为永久删除。
- 非空目录整体移入，符号链接只移动链接本身。
- 检查版本，不允许直接删除配置根目录。

四、终端执行与进程管理

必须提供：
start_process、read_process_output、interact_process、
list_processes、stop_process。

要求：

1. 命令真实运行在这台电脑上，使用当前用户身份和本机可用的 Shell。macOS 默认 /bin/zsh，其他系统选择合适的 Shell。
2. 每次启动必须指定绝对工作目录，返回会话 ID、进程状态、stdout/stderr、退出码及信号。
3. 支持运行脚本、调用已安装的程序、安装依赖、启动开发服务和长时间运行的命令。
4. 工具等待时间与命令执行期限分开：命令默认 120 秒超时；timeout_ms=0 明确选择不限运行时间。长任务先返回会话 ID，之后继续查询。
5. 支持输出分页与等待新输出，保留 stdout/stderr 来源。缓冲区有界，截断或丢弃旧输出时明确报告。
6. 支持跨工具调用发送 stdin、换行和 EOF，避免输入关闭、管道错误导致服务崩溃。
7. 支持列出受管会话，也能查询系统进程。系统查询默认省略其他进程的环境变量和完整命令参数。
8. 停止工具只操作自己管理的会话，正确处理普通子进程和进程组；按实际操作系统实现。
9. 支持超时终止和必要的强制停止。正常关闭本机 MCP 服务时，清理它管理的进程。
10. 默认最多 8 个并发任务、64 个历史会话，每个会话保留约 2 Mi 字符输出。明确会话和内存输出不能跨服务重启恢复。
11. 这一版支持标准输入输出管道，不要求 PTY、全屏终端或鼠标键盘控制。
12. 对已另行守护化的程序、Docker daemon 创建的容器等，说明需要使用其自身的管理命令，不虚构进程追踪能力。

权限边界必须写清楚：

Shell 具有当前用户的真实执行权限，运行的程序可能修改、覆盖或永久删除文件。“删除只进回收站”是文件删除工具的约定，不是 Shell 的安全沙箱。

用户要求删除文件时，仍使用 delete_path，不能用终端绕过回收站约定。不要通过命令黑名单声称实现了可靠隔离。

五、代码结构分析

集成 codebase-memory-mcp 的只读分析能力，核对当前上游版本、安装方式和工具帮助，提供以下接口：

codebase_list_projects
codebase_index_status
codebase_check_index_coverage
codebase_search_graph
codebase_trace_path
codebase_query_graph
codebase_get_code_snippet
codebase_get_file_outline
codebase_search_code
codebase_get_architecture
codebase_get_graph_schema
codebase_compare_graphs
codebase_detect_changes

支持符号搜索、调用关系、源码片段、架构、只读图查询和变更影响分析。保留上游参数、分页及错误，不悄悄降低能力。

索引为空、过期或不完整时必须说明，并回到当前源码验证。用一个小型样本项目验证索引与分析能力；不要自动扫描全部磁盘建立索引。

六、部署和运行

1. 优先复用已有依赖，保持实现简单，提供完整源码、依赖声明和启动配置。
2. 路径按本机实际环境生成，不写死别人的用户名、设备名或安装目录。
3. 配置当前用户登录自启、异常退出恢复和合理的重启间隔；同时提供明确的启动、停止、停用自启方法，避免多个实例竞争同一隧道。
4. macOS 使用 launchd 时，将启动日志放在当前用户 Library/Logs 下，核对 PATH、运行用户及文件权限。
5. 增加调用元数据审计：记录工具、时间、状态、会话 ID、路径/命令摘要，不记录密钥、文件正文、原始命令、stdin 或输出正文。
6. 写入和执行前先保证审计可用；完成后的审计失败必须如实告警，不能把已经发生的操作报告为未执行。
7. 清楚说明电脑休眠、断网、服务重启时的行为。不要擅自重启整台电脑或干扰其他人的服务。

七、验收和交付

必须分别验证：

- 本地测试：文件操作、版本冲突拒绝、回收站删除及失败处理、文档和视觉解析、终端退出码、交互输入、超时、输出分页、进程组停止、关闭清理、代码分析接口。
- 隧道运行：健康、就绪、实际控制面轮询，而不只检查进程或端口存在。
- 网页真实调用：在我的 ChatGPT 中新建一个用于验收的测试对话，选择这个插件，实际读取和修改临时文件、调用终端命令并读回结果。不能用本地 Shell 或其他插件的执行结果冒充这个插件的远程结果。
- 真实服务：通过新增工具启动临时 HTTP 服务，实际请求检查响应，再停止并确认端口关闭、测试进程没有遗留。
- 回收站：确认测试文件原路径消失，在回收站中找到对应文件且内容一致，不清空回收站。
- 服务重启与恢复：验证常驻配置及恢复行为，明确受管会话是否结束。

按以上工具分组，目标是 32 个工具，但数量不能替代行为验收。任何依赖缺失、账号权限不足或功能未通过，都准确列为未完成，继续其他独立工作，不静默缩减需求。

最终交付：项目位置、源码和运行配置、网页插件入口、工具及权限清单、启动停止方法、实际验证证据和剩余缺口。只有网页端真实调用成功，才能报告远程接入验收完成。
```
